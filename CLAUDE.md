# Engineering rules

Rules for anyone (human or agent) changing this repo.

## Where code runs
- Nothing runs on the maintainer's laptop except file edits, git, and read-only commands (`ls`, `cat`, `grep`, `curl`, `gh`).
- Tests, lint, and the local smoke pipeline run in GitHub Actions (`.github/workflows/ci.yml`). Push and read the CI result.
- Data generation runs in Colab notebook 01 (CPU). Training, explanation, publishing, and Space deploy run in Colab notebook 02 (GPU).
- Colab results are read from run reports at `https://huggingface.co/rohanjain2312/trade-settlement-fail-predictor/resolve/main/runs/latest.json`.

## Data and features
- All data is synthetic and generated by code in this repo. Never add real trade data.
- `src/features/definitions.py` is the single source of truth for the 20 model features, their types, and their order.
- `failed`, `fail_reason`, `scenario_mask`, IDs, dates, and raw notional are never model inputs. `tests/test_no_label_leakage.py` enforces this.
- Rolling features use only outcomes known on the trade date (settle date strictly before the trade date).
- If a distinctness check fails, change the generator, not the feature definitions.

## Modeling
- Splits are by trade date with a gap of business days between train, validation, and test.
- SMOTENC runs only inside an `imblearn` Pipeline, so it only ever sees training data or training folds.
- Thresholds and calibration are fitted on validation data, never on test.
- Accuracy is not a headline metric. Report PR-AUC, recall at fixed precision, recall in the top k percent, and Brier score.

## Reproducibility
- Fixed seeds everywhere. Every number shown in the app must be reproducible from `config/` and the seed.
- Run mode is set in `config/run.yaml` (`smoke`, `full`, `auto`), so a commit controls what Colab runs.
- Colab pins live in `requirements-colab.txt`. Do not upgrade Colab's CUDA, numpy, or pandas stack unless a pin requires it.

## Secrets
- The Hugging Face token lives only in Colab Secrets as `HF_TOKEN`. Never hardcode, commit, log, or print it.
- Run reports redact anything that looks like a token before upload.

## Checkpointing
- Every stage writes outputs and `manifest.json` in one all-or-nothing commit to the work repo.
- A stage is skipped only if it is done, its outputs match their checksums, and its config hash and code hash are unchanged.
- Checkpoint at a coarse grain (a month, a few trials, N boosting rounds, a SHAP chunk), never per row.

## Style
- Small commits with clear messages. Keep CI green.
- Simplest code that meets the spec. No speculative abstractions or configuration.
- Do not delete or weaken a test to make CI pass. If a test is wrong, fix it and say why in the commit message.
- Plain wording in docs. Say plainly that data is synthetic. Do not present any external business figures as results of this project.
